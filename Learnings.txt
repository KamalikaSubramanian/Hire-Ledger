Why do we use caching then?
The main reason is not to survive server restarts.

It's to avoid creating multiple connections while the server is already running.

In Next.js development mode:

Every time you save a file, Fast Refresh/Hot Reload can reload modules.
Without caching, mongoose.connect() might be called repeatedly.
This can lead to many unnecessary MongoDB connections and errors like:
"Too many connections"
"Cannot overwrite model once compiled"

Using global.mongooseConnection ensures that the running server reuses the existing connection.

What is a Webhook?

A webhook is simply:
One server automatically sending information to another server when an event occurs.

What is a webhook?
A webhook is an HTTP callback where one system automatically sends data to another system when a specific event occurs. It enables event-driven communication without requiring repeated polling.


Why use webhooks instead of checking on every request?
Webhooks are more efficient because they only trigger when relevant events occur, reducing unnecessary database queries and improving application performance and scalability.

Q1. Why store extractedText?
Parsing a PDF is relatively expensive. By extracting the text once during upload and storing it, the application can perform AI analysis much faster without repeatedly reading the PDF.

Q2. Why use fileUrl instead of storing the PDF in MongoDB?
Large files are better stored in object storage services like Cloudinary. MongoDB stores only the metadata and URL, making the database smaller and improving performance.

Q3. Why keep multiple resume versions?
Users often tailor resumes for different roles. Versioning allows them to retain previous resumes and choose the appropriate one for each job application.

Why not store Missing Skills here?

A common question is:
Why don't we store missingSkills in the Skill collection instead of Application?

We intentionally keep them in the Application model because missing skills are specific to a job description.

For example:

Missing
AWS
Docker

Missing
Kubernetes
Redis

If we stored missing skills globally, we'd lose the context of which job they were missing for.

Instead:

Application.missingSkills → Missing for that specific application.
Skill → User's known skills and profile.

This separation keeps the data meaningful and easier to analyze.

Q1. Why separate Skill from Application?
Application stores job-specific information, while Skill stores user-specific information. Separating them avoids duplication, makes analytics easier, and follows normalization principles.

Q3. Why store proficiency as a number?
A numeric scale is flexible. It can be displayed as percentages, progress bars, or mapped to labels like Beginner, Intermediate, and Advanced.

Q1. Why keep notifications in a separate collection?
Notifications are user activity records, not part of the application or resume data. A separate collection keeps concerns separated, allows independent querying, and makes it easy to implement features like unread counts, pagination, and notification history.

Q2. Why use isRead instead of deleting notifications?

Q1. Why use Server Actions instead of accessing MongoDB in React components?
Server Actions execute securely on the server, keeping database credentials and business logic away from the client. They also centralize data access and make the application easier to maintain.

Q2. Why organize actions by model?
Grouping actions by model follows the Single Responsibility Principle. It improves readability, simplifies maintenance, and makes it easier to locate related database operations.

Q3. Why avoid any in action parameters?
Using explicit TypeScript interfaces improves type safety, editor support, and reduces runtime errors by catching invalid data during development.

One-line definitions (Good for interviews)

1. File
A browser object representing an uploaded file, including metadata and binary content.
It contains:
filename
size
MIME type
file contents

2. ArrayBuffer
An ArrayBuffer is the browser's representation of the file's binary contents. It stores raw bytes only.

Created using:
const bytes = await file.arrayBuffer();
Example output:
ArrayBuffer {
  byteLength: 201346
}

3. Buffer
Node.js's binary data type used to efficiently manipulate and transfer binary data.

Created using:
const buffer = Buffer.from(bytes);

Buffer provides many helper methods:
buffer.length
buffer.toString()
buffer.slice()

4. Readable Stream
A mechanism for reading or sending data in small chunks instead of loading the entire file into memory at once.

Created using:
Readable.from(buffer)

5. upload_stream()
A Cloudinary API that accepts streamed binary data for uploading files.

Cloudinary creates an upload destination.
const uploadStream =
cloudinary.uploader.upload_stream(...)

6. .pipe()
A Node.js method that connects a readable stream to a writable stream, allowing data to flow automatically from source to destination.
Readable.from(buffer).pipe(uploadStream);

7.Cloudinary returns something like:

{
  "public_id": "hire-ledger/resumes/jd82hd",
  "secure_url": "https://res.cloudinary.com/gbndrylk/raw/upload/v1758.../Resume.pdf"
}

--public_id : This is Cloudinary's unique ID.

Example:
hire-ledger/resumes/jd82hd

You use it later to delete the file.

await cloudinary.uploader.destroy(publicId, {
  resource_type: "raw",
});

--secure_url: This is the public HTTPS URL.

Example:
https://res.cloudinary.com/gbndrylk/raw/upload/v1758.../Resume.pdf

Anyone with this URL can view or download the file (unless you've configured access restrictions).
